# วิธีทดสอบ Short URL

เปิด [เว็บทดสอบออนไลน์](https://project-short-url-qrrz.vercel.app) แล้วสมัครบัญชีใหม่ ไม่ต้องใช้ Username/Password ที่เตรียมไว้ล่วงหน้า หากติดตั้งในเครื่อง ใช้ [http://localhost:5173](http://localhost:5173) หลังทำตาม [README](../README.md)

รายการด้านล่างระบุวิธีทดสอบและผลลัพธ์ที่คาดหวัง สำหรับการตรวจผ่านหน้าจอ

## ฟังก์ชันตามโจทย์

| รายการ | วิธีทดสอบ | ผลลัพธ์ที่คาดหวัง |
|---|---|---|
| สร้าง Short URL | เข้าสู่ระบบ กรอก `https://www.synerry.com` แล้วกดสร้างลิงก์ | ได้ Short URL และแสดง URL ต้นฉบับถูกต้อง |
| เปิด URL ปลายทาง | เปิด Short URL ในแท็บใหม่หรือหน้าต่างไม่ระบุตัวตน | ไปยัง URL ต้นฉบับได้โดยไม่ต้อง Login |
| รักษา Query / Fragment | สร้างลิงก์จาก `https://example.com/?source=demo#section` แล้วเปิด | ส่งต่อ URL พร้อม `?source=demo#section` |
| QR Code | ขอ QR ของลิงก์ ดาวน์โหลดแล้วสแกนด้วยมือถือ | QR เปิด Short URL แล้วไปยัง URL ต้นฉบับ |
| ประวัติลิงก์ | เปิดหน้าประวัติหลังสร้างลิงก์ | มี URL ต้นฉบับ Short URL สถานะ และยอดคลิก |
| สถิติการคลิก | จดยอดเดิม เปิด Short URL หนึ่งครั้ง แล้วโหลดประวัติ/แดชบอร์ดใหม่ | ยอดคลิกเพิ่มขึ้น และมีข้อมูลในสถิติของช่วงวันที่นั้น |

การสแกนจากมือถือให้ใช้ Short URL บนเว็บออนไลน์ เพราะ `localhost` บนมือถือหมายถึงตัวมือถือเอง การนับคลิกเป็นเหตุการณ์เปิดลิงก์ ไม่ใช่จำนวนบุคคลที่ไม่ซ้ำ และการเพิ่มคลิกไม่ยืนยันว่าเว็บไซต์ปลายทางโหลดสำเร็จ

## ฟังก์ชันเพิ่มเติม

| รายการ | วิธีทดสอบ | ผลลัพธ์ที่คาดหวัง |
|---|---|---|
| สมัคร / เข้าสู่ระบบ | สมัครด้วยอีเมลใหม่ แล้ว Login ด้วยรหัสผ่านที่ตั้ง | เข้าสู่ระบบและจัดการลิงก์ของบัญชีได้ |
| แก้ชื่อบัญชี | เปิดหน้าโปรไฟล์ แก้ชื่อ บันทึกแล้ว Refresh | แสดงชื่อใหม่หลังโหลดหน้าอีกครั้ง |
| ออกจากระบบ | กด Logout แล้วเปิดหน้าที่ต้องเข้าสู่ระบบ | ต้อง Login อีกครั้งก่อนจัดการข้อมูล |
| Alias | สร้างลิงก์โดยกำหนด Alias ที่ยังไม่มี เช่น `demo-2026-a` | Short URL ใช้ Alias ที่กำหนด |
| Alias ซ้ำ / ชื่อสงวน | สร้างอีกลิงก์ด้วย Alias เดิม หรือใช้ `login` | แจ้งว่าใช้ชื่อนั้นไม่ได้และไม่สร้างลิงก์ซ้ำ |
| วันหมดอายุ | ตั้งเวลาที่ใกล้ถึงในอนาคต เปิดก่อนและหลังเวลานั้น | เปิดได้ก่อนหมดอายุ หลังหมดอายุไม่ส่งต่อ |
| แก้วันหมดอายุ | เปลี่ยนวันหมดอายุเป็นเวลาในอนาคต หรือล้างวันหมดอายุ | บันทึกและใช้ค่าล่าสุดในการตรวจลิงก์ |
| ปิด / เปิดลิงก์ | ปิดการใช้งาน เปิด Short URL จากแท็บใหม่ แล้วเปิดใช้งานคืน | ขณะปิดไม่ส่งต่อ เมื่อเปิดคืนและยังไม่หมดอายุส่งต่อได้ |
| ค้นหา / กรอง / แบ่งหน้า | สร้างหลายรายการ ค้น URL หรือรหัส กรองสถานะและเปลี่ยนหน้า | แสดงเฉพาะรายการตรงเงื่อนไขและจำนวนหน้าถูกต้อง |
| สถิติตามช่วงวันที่ | เลือกช่วงวันที่ที่มีการคลิก แล้วเปรียบเทียบช่วงที่ไม่มี | กราฟและยอดคลิกสอดคล้องกับช่วงที่เลือก |
| QR หลายรูปแบบ | ดาวน์โหลดทั้ง PNG และ SVG | เปิดไฟล์ได้และเข้ารหัส Short URL เดียวกัน |

ทดสอบวันหมดอายุด้วยเวลาที่ตั้งใจให้ถึงระหว่างการตรวจ หากต้องการเปิดลิงก์คืนหลังทดสอบปิดใช้งาน ต้องตรวจว่ายังไม่หมดอายุด้วย

## ตรวจข้อมูลไม่ถูกต้องและสิทธิ์

| รายการ | วิธีทดสอบ | ผลลัพธ์ที่คาดหวัง |
|---|---|---|
| URL ไม่ถูกต้อง | เว้น URL ว่าง หรือกรอก `javascript:alert(1)` | แจ้งข้อมูลไม่ถูกต้องและไม่สร้างลิงก์ |
| Login ไม่ถูกต้อง | ใช้รหัสผ่านผิด | ไม่เข้าสู่ระบบ |
| อีเมลซ้ำ | สมัครซ้ำด้วยอีเมลเดิม | ไม่สร้างบัญชีซ้ำ |
| แยกข้อมูลบัญชี | สร้างลิงก์ด้วยบัญชี A แล้ว Login บัญชี B ในอีก Browser | บัญชี B ไม่เห็นรายการหรือสถิติของ A |
| ตรวจสิทธิ์ API | ใช้ Session ของ B ขอรายละเอียด แก้ไข ขอ QR หรือสถิติด้วย link ID ของ A | API ไม่คืนข้อมูลและไม่อนุญาตให้แก้ไข |
| ลิงก์ไม่พบ | เปิด Short Code ที่ไม่มีในระบบ | แจ้งไม่พบลิงก์และไม่ส่งต่อ |

ผู้ที่ตรวจ API ใช้รายละเอียดเส้นทางและสถานะตอบกลับจาก [API Contract](api.md) เช่น 401 เมื่อไม่มี Session, 404 เมื่อไม่ใช่เจ้าของ และ 410 เมื่อลิงก์ปิดหรือหมดอายุ

## ตรวจโค้ดและการทำงานอัตโนมัติ

รันจาก repository root หลังติดตั้ง Dependencies และสร้าง Prisma Client:

```sh
npm run verify
```

ตรวจ TypeScript, lint, unit/API tests และ build ของทุก workspace

เปิด PostgreSQL ในเครื่อง แล้วรัน Integration ซึ่งใช้และล้างข้อมูลเฉพาะฐาน `short_url_test`:

```sh
npm run test:integration
```

สำหรับ E2E ให้ปิด `npm run dev` ก่อน เปิดฐานข้อมูลพัฒนาไว้ แล้วรัน:

```sh
npx playwright install chromium
npm run test:e2e
```

Playwright เริ่มระบบให้เองและทดสอบผ่าน Browser บน Desktop, Tablet และ Mobile โดยสร้างข้อมูลในฐานพัฒนา ดู [การติดตั้งฐานข้อมูล](local-postgres.md) สำหรับวิธีเริ่ม/หยุด

## ตรวจหลัง Deploy

1. ทดสอบสร้างลิงก์ เปิด Short URL สแกน QR ประวัติ และสถิติผ่านเว็บออนไลน์ตามตารางด้านบน
2. ตรวจ Gateway `/healthz` และแต่ละ service `/readyz` ว่าตอบ 200
3. เรียก API ของ service โดยไม่มี Internal Key ต้องได้ 403

`/healthz` ตรวจตัวแอป ส่วน `/readyz` ของ service ตรวจการเชื่อมต่อฐานข้อมูล ข้อผิดพลาดของบริการที่พึ่งพากันดูใน [Architecture](architecture.md)
